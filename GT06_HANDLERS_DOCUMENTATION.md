# GT06 Protocol Message Handlers Documentation\n\n## Overview\nYour GT06 protocol implementation now includes comprehensive handlers for all message types. Here's what each handler does:\n\n## Message Handlers\n\n### 1. `handleWifiMessage()`\n**Purpose**: Processes WiFi positioning data from GPS devices\n\n**What it does**:\n- Decodes WiFi access point information (MAC addresses and signal strength)\n- Supports different WiFi message formats (MSG_WIFI, MSG_WIFI_2, MSG_WIFI_3, MSG_WIFI_4)\n- Extracts WiFi data for location triangulation when GPS is not available\n- Stores WiFi access points in `position.attributes.wifiAccessPoints`\n\n**Use case**: Indoor positioning, GPS backup when satellite signal is weak\n\n### 2. `handleLBSMessage()`\n**Purpose**: Processes LBS (Location Based Service) cell tower data\n\n**What it does**:\n- Decodes cell tower information (MCC, MNC, LAC, CID)\n- Handles multiple cell towers for better positioning accuracy\n- Supports different LBS message types (MSG_LBS_MULTIPLE_1/2/3, MSG_LBS_ALARM, etc.)\n- Processes alarm data in LBS messages\n- Handles address responses from cell tower positioning\n\n**Use case**: Location when GPS is unavailable, cell tower triangulation\n\n### 3. `handleMultimedia()`` \n**Purpose**: Processes multimedia data (photos/videos) from devices\n\n**What it does**:\n- Decodes multimedia message headers (type, format, size)\n- Handles photo and video data transmission\n- Supports JPEG photos and H.264 video formats\n- Stores multimedia data as base64 encoded strings\n- Processes multimedia data sent in chunks\n\n**Use case**: Security cameras, dashcams, photo evidence from GPS devices\n\n### 4. `handlePeripheral()`\n**Purpose**: Processes data from external sensors connected to GPS device\n\n**What it does**:\n- Decodes peripheral sensor data (temperature, humidity, fuel, door sensors)\n- Supports VL842 peripheral format\n- Handles different sensor types:\n  - Temperature sensors (°C)\n  - Humidity sensors (%)\n  - Fuel level sensors\n  - Door/window sensors (open/closed)\n- Stores sensor data in position attributes\n\n**Use case**: Fleet management, cold chain monitoring, security systems\n\n## Message Flow\n\n```\nGPS Device → Raw Binary Data → GT06 Decoder → Message Handler → Processed Data\n```\n\n### Example Data Flow:\n\n1. **WiFi Message**: Device scans WiFi → Sends MAC addresses + RSSI → Handler extracts positioning data\n2. **LBS Message**: Device reads cell towers → Sends tower IDs → Handler processes for location\n3. **Multimedia**: Camera takes photo → Device sends image data → Handler processes media\n4. **Peripheral**: Temperature sensor reads 25°C → Device sends sensor data → Handler extracts temperature\n\n## Integration with Your System\n\nThese handlers integrate with your existing GPS tracking system:\n\n- **Real-time Updates**: All processed data is emitted via WebSocket (`locationUpdate` events)\n- **Database Storage**: Position data with sensor information is stored in MongoDB\n- **API Access**: Sensor data available through your REST API endpoints\n- **Alerts**: Alarm conditions trigger notifications\n\n## Supported Device Features\n\nYour implementation now supports:\n- ✅ Basic GPS tracking\n- ✅ Engine control (lock/unlock)\n- ✅ WiFi
